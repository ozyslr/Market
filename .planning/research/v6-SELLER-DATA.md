# v6 Admin Seller Control Center — Seller Data & Service Audit

**Researched:** 2026-06-08
**Scope:** Codebase-grounded inventory of all seller/admin data and service capabilities that exist and can be surfaced in the v6 Admin Seller Control Center.

---

## 1. Overview

The codebase already contains a rich but fragmented set of data collections and service modules covering every dimension of a seller's lifecycle: onboarding & KYC (`sellerApplications`, `sellers`), store customisation (`storeConfigs`, `sellerMenus`, `storeContentBlocks`), performance tiers (`sellerTiers`), financial accounting (an immutable server-side `ledger` + client-facing `sellerBalances`, `payoutRequests`, `payoutSchedules`, `commissionRules`, `commissionTransactions`), product moderation (`products`, `productApprovals`), order fulfilment (`orders`, sub-order pattern in progress), post-order flows (`returnRequests`, `complaints`), compliance logging (`auditLogs`), and API credential management (`apiKeys`). The existing `AdminSellerView` page (`src/pages/AdminSellerView.tsx`) already loads seven of these domains in parallel and supports KYC approve/reject via two server endpoints (`/api/admin/seller/:id/approve-tr` and `/approve-eu`). However the page is a read-heavy display with only the approve/reject write path wired; all other admin write actions (suspend/ban, tier override, commission override, payout approval, coupon management) are either missing or live in separate pages. The Control Center milestone consolidates them into one screen per seller.

## 3. Gaps — What an Admin Would Want That Does NOT Exist Yet

### 3.1 Data gaps

| Gap                                          | What's Missing                                                                                                                                                                                   | Impact                                                                                                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| No per-seller tier override                  | `sellerTiers` stores global tier configs; there is no `sellerTierOverride` collection or field on the `sellers` doc to manually assign a seller to a tier regardless of their performance score. | Admin cannot manually promote/demote a seller to a tier.                                                                                             |
| Trust score not persisted                    | `computeTrustScore()` is a pure function; result is never stored in Firestore. No `sellerTrustScores` collection.                                                                                | Cannot show trust score history, cannot query by trust level.                                                                                        |
| Performance score not persisted              | `calcSellerPerformance()` is compute-on-read with placeholder values for `shipSpeedScore` and `responseRate`. No `sellerPerformanceSnapshots` collection.                                        | Score is unstable/non-deterministic across page loads.                                                                                               |
| Complaints missing `sellerId`                | `Complaint` type has `productId` and `buyerId` but no `sellerId` field.                                                                                                                          | Filtering all complaints for a given seller requires a secondary join through products — expensive and fragile.                                      |
| No admin note / suspension history           | `sellers` doc has `adminNote` (single string) and `suspendedUntil` but no log of previous suspensions, ban reasons, or admin action history at the entity level.                                 | Only the most recent note is visible; prior admin actions not reconstructible from seller doc alone (audit log exists but requires cross-reference). |
| No seller-level commission override document | Per-seller rate is encoded inside `CommissionRule.sellerOverrides{}` as a key in the global rule; no standalone `sellerCommissionOverride` doc.                                                  | To change a seller's rate, admin must load and mutate the global rule object — not atomic, race-condition-prone.                                     |
| No seller warning/strike system              | No `sellerWarnings` or `sellerStrikes` collection.                                                                                                                                               | Cannot implement graduated enforcement (warn → suspend → ban) with evidence trail.                                                                   |
| No payout destination on `sellers` doc       | Bank IBAN appears only in `sellerApplications.bankIban`; not promoted to the active `sellers` doc.                                                                                               | Admin cannot see current payout destination without navigating to application.                                                                       |
| Complaint resolution lacks refund linkage    | `resolveComplaint()` does not trigger a refund or link to `returnRequests`/`ledger`.                                                                                                             | Complaint resolution and financial resolution are disconnected workflows.                                                                            |

### 3.2 Functional gaps (no server endpoints exist)

| Gap                                        | Required Action                                                           | Current State                                                                |
| ------------------------------------------ | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Suspend / ban seller                       | Needs server endpoint to set `sellers.status` + log audit + notify seller | Only client-side `updateSeller()` (no auth guard, no audit trail wired)      |
| Admin revoke API key (bypass owner check)  | Server endpoint `DELETE /api/admin/seller/:id/api-keys/:keyId`            | `revokeApiKey()` checks seller ownership; admin path absent                  |
| Admin force-override tier                  | Endpoint to write per-seller tier override                                | Not implemented                                                              |
| Admin adjust balance / manual ledger entry | `POST /api/admin/seller/:id/balance/adjust`                               | Not implemented (immutable ledger exists but no admin adjustment entry path) |
| Admin view ledger for a specific seller    | `GET /api/admin/seller/:id/ledger`                                        | Finance routes only serve authenticated seller; admin view not wired         |
| Bulk payout approval                       | Admin bulk-update payout statuses                                         | Only single `updatePayoutStatus()`                                           |

## 4. Reuse Recommendations

### Call existing client services directly (safe, no new endpoints needed)

| Use case                                 | Service + function                                                                                                                            |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Load seller profile                      | `src/services/userService.ts` → `getSellers()` + filter, or `getDoc(db, 'sellers', sellerId)` directly (as current `AdminSellerView` does)    |
| Load store config / menu / blocks (read) | `sellerStoreService.getStoreConfig()`, `sellerMenuService.getSellerMenu()`, `storeContentService.getContentBlocks()`                          |
| Load KYC application + docs              | `sellerApplicationService.getApplications()` filtered by `userId`                                                                             |
| KYC approve / reject                     | `sellerApplicationService.reviewApplication()` + server endpoint `/api/admin/seller/:id/approve-{tr,eu}` (already wired in `AdminSellerView`) |
| Load payout history + balance            | `sellerPayoutService.getPayoutHistory()`, `sellerPayoutService.getSellerBalance()`                                                            |
| Approve / reject payout                  | `sellerPayoutService.updatePayoutStatus()`                                                                                                    |
| Load commissions                         | `commissionService.getSellerCommissions()`                                                                                                    |
| Release commissions                      | `commissionService.releaseCommissions()`                                                                                                      |
| Load return requests                     | `returnService.getAllReturnRequests()` filtered by `sellerId`                                                                                 |
| Update return status                     | `returnService.updateReturnStatus()`                                                                                                          |
| Load complaints (by product join)        | `complaintService.getComplaintsByProduct()` per seller product — needs loop                                                                   |
| Resolve complaint                        | `complaintService.resolveComplaint()`                                                                                                         |
| Product moderation                       | `moderationService.approveProduct()`, `moderationService.rejectProduct()`, `moderationService.requestChanges()`                               |
| Audit log (read + write)                 | `auditLogService.getAuditLogs()` filtered by `entityId = sellerId`; `audit()` shorthand for all admin writes                                  |
| Performance score                        | `sellerRatingService.calcSellerPerformance()`, `sellerRatingService.getSellerStarSummary()`                                                   |
| Tier configuration                       | `sellerTierService.getAllTierConfigs()`, `sellerTierService.updateTierConfig()`                                                               |
| Coupons                                  | `sellerCouponService.getSellerCoupons()`, `sellerCouponService.updateCoupon()`                                                                |
| API keys (view + revoke via owner path)  | `apiKeyService.getApiKeys()`, `apiKeyService.revokeApiKey()`                                                                                  |
| Analytics summary                        | `sellerAnalyticsService.getSellerAnalytics()`                                                                                                 |

### Requires new server endpoints (trust, authority, or missing paths)

| Use case                          | Recommended endpoint                            | Reason                                                                                                              |
| --------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Suspend / ban / activate seller   | `POST /api/admin/seller/:id/status`             | Must be server-side: needs audit trail, notification, Firebase Admin SDK to update Auth custom claims if applicable |
| Admin revoke any API key          | `DELETE /api/admin/seller/:id/api-keys/:keyId`  | Bypass seller ownership check safely                                                                                |
| Per-seller commission override    | `PUT /api/admin/seller/:id/commission-override` | Atomic write isolated from global rule; server validates range                                                      |
| Manual ledger adjustment          | `POST /api/admin/seller/:id/ledger/adjust`      | Append-only ledger is server-only; client SDK writes blocked by Firestore rules                                     |
| Admin view seller ledger          | `GET /api/admin/seller/:id/ledger`              | Existing `GET /api/seller/transactions` serves authenticated seller only                                            |
| Per-seller tier override          | `PUT /api/admin/seller/:id/tier-override`       | Write to `sellers.tierOverride` field; server validates tier is valid enum                                          |
| KYC document signed URL           | `GET /api/kyc/signed-url/:storagePath`          | Already exists (used in current `AdminSellerView`)                                                                  |
| Add/resolve seller warning/strike | `POST /api/admin/seller/:id/warnings`           | New collection `sellerWarnings`; requires design                                                                    |
