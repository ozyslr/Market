    export interface CheckoutItem {

      name: string;
      price: number;
      subMerchantKey: string;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> API `/api/iyzico/init` | Untrusted client sends order items; server authoritative for pricing |
| API -> iyzico | Server constructs marketplace payment request with subMerchant splits |
| iyzico -> API callback | Untrusted callback; signature verification required |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-001 | Tampering | POST /api/iyzico/init | mitigate | Server-side pricing: client sends only productId+quantity; server calculates totals and commission via commissionEngine |
| T-02-002 | Spoofing | iyzico callback | mitigate | Server-to-server callback handles raw body; payment status verified via iyzico retrieveCheckoutForm (not client-provided status) |
| T-02-003 | Information Disclosure | IPaymentProvider | mitigate | Interface methods return only payment-page URLs (not raw SDK responses); no API keys exposed |
| T-02-004 | Elevation of Privilege | subMerchantKey selection | mitigate | subMerchantKey sourced from seller records (not client input); client cannot specify which subMerchant gets paid |
| T-02-SC | Tampering | npm iyzipay package | accept | iyzipay 2.0.67 is [ASSUMED] per Package Legitimacy Audit in RESEARCH.md; no new packages installed in this plan |
