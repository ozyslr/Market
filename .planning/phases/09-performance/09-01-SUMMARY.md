# Phase 9 Plan 1: manualChunks + Bundle Budget Summary

Vite `manualChunks` vendor splitting reduces the original two 1.6MB/1.2MB chunks into 10 vendor buckets plus lazy-loaded routes. A CI-ready bundle budget script enforces per-chunk gzip limits using only Node built-ins.

## What Was Built

### Task 1: manualChunks vendor splitting

Added `build.rollupOptions.output.manualChunks` function to `vite.config.ts` with 10 vendor buckets:

| Chunk | Contents | Raw | Gzip |
|-------|----------|-----|------|
| vendor-react | react, react-dom, react-router-dom, react-is, scheduler | 235KB | 75KB |
| vendor-firebase-firestore | @firebase/firestore, @grpc, protobufjs | 401KB | 93KB |
| vendor-firebase | firebase (app, auth, storage) + firebase-admin | 378KB | 84KB |
| vendor-charts | recharts, d3-* | 400KB | 117KB |
| vendor-ui | lucide-react, @google/model-viewer, react-helmet-async | 342KB | 94KB |
| vendor-three | three.js | 807KB | 223KB |
| vendor-motion | motion (framer-motion v12) | 129KB | 42KB |
| vendor-utils | axios, papaparse, clsx, tailwind-merge, zod | 47KB | 16KB |
| vendor-dnd | @dnd-kit/* | 44KB | 15KB |
| vendor-stripe | @stripe/* | 14KB | 5KB |

- PWA SW intact: 118 precache entries (5,601KB total)
- No circular chunk warnings
- Build time: ~27s

### Task 2: Bundle budget CI check

Created `scripts/check-bundle-size.mjs` (zero new dependencies — uses `fs`, `path`, `zlib` only). Added `npm run build:check` script.

Budgets enforced (gzip):
- Vendor chunks (`vendor-*`): 250KB
- Main entry (`index-*`): 350KB
- Lazy routes: 500KB

All 97 chunks pass. vendor-three is the tightest at 87.2% of its 250KB vendor budget.

## Deviations from Plan

### Rule 1/2 Auto-fixes

**1. [Rule 1 - Bug] vendor-three exceeds 500KB raw chunk warning**
- **Found during:** Task 1 build verification
- **Issue:** three.js is an 807KB raw / 223KB gzip monolithic library. Vite's raw-size warning fires, but gzip is well under the 500KB gzip budget. Cannot split a single npm package further.
- **Fix:** Kept chunkSizeWarningLimit at 500KB and isolated three.js in its own `vendor-three` chunk. The gzip budget (223KB vs 250KB vendor cap) is the real enforcement gate — the CI script checks gzip, not raw.
- **Files modified:** vite.config.ts
- **Commit:** 11de16d

**2. [Rule 1 - Bug] Circular chunk warning (vendor-charts <-> vendor-misc)**
- **Found during:** Task 1 iterative build testing
- **Issue:** Catch-all `vendor-misc` bucket caused circular dependency with `vendor-charts` (d3 sub-packages cross-referencing).
- **Fix:** Removed catch-all `vendor-misc`. Unknown node_modules packages fall through to Vite's default splitting. This eliminates the circular chunk.
- **Files modified:** vite.config.ts
- **Commit:** 11de16d (same commit)

**3. [Rule 2 - Missing critical] vendor-firebase exceeded 500KB raw at first build**
- **Found during:** Task 1 first build
- **Issue:** Single `vendor-firebase` chunk at 776KB raw included both core Firebase SDK and the large Firestore/grpc/protobufjs stack.
- **Fix:** Split into `vendor-firebase-firestore` (firestore + grpc + protobufjs) and `vendor-firebase` (app, auth, storage + admin). Both now under 500KB raw.
- **Files modified:** vite.config.ts
- **Commit:** 11de16d (same commit)
