<objective>
Vertical slice for REV-01: close the verified-purchase gap. A buyer submits a review through a new server endpoint that confirms a Delivered SubOrder via Firebase Admin before writing the review with server-set `verified: true` and `status: 'approved'`. The client's `addReview` direct-write path is removed; Firestore rules deny client writes to `reviews`. The verified badge renders on the review.

Purpose: Closes the security gap where `addReview` trusts a caller-supplied `verified` boolean (D-01). Foundation slice that 07-02 (photo reviews) builds on.
Output: New Express route, hardened reviewService, ReviewForm wired to the endpoint, ReviewCard badge, Firestore rules.
</objective>

<threat_model>

## Trust Boundaries

| Boundary                    | Description                                                     |
| --------------------------- | --------------------------------------------------------------- |
| client -> POST /api/reviews | Untrusted review payload (rating, comment, photos) crosses here |
| client -> Firestore reviews | Direct client writes must be impossible                         |

## STRIDE Threat Register

| Threat ID | Category    | Component                               | Disposition | Mitigation Plan                                                                                                 |
| --------- | ----------- | --------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------- |
| T-07-01   | Spoofing    | client-set `verified` flag              | mitigate    | Server sets verified:true only after confirming a Delivered SubOrder via Admin SDK; req.body.verified ignored   |
| T-07-02   | Tampering   | client direct write to reviews          | mitigate    | firestore.rules `allow create: if false`; all writes via Admin SDK server path                                  |
| T-07-03   | Elevation   | unverified user posting approved review | mitigate    | 403 unless a Delivered SubOrder contains the product; status:'approved' server-set                              |
| T-07-04   | Tampering   | oversized/invalid payload               | mitigate    | Zod schema: rating 1-5, comment max 2000, photos max 5                                                          |
| T-07-05   | Repudiation | duplicate reviews inflating rating      | mitigate    | Dedup check returns 409 on existing approved review (checkUserReview analog)                                    |
| T-07-SC   | Tampering   | npm/pip/cargo installs                  | mitigate    | No new packages introduced this plan; zod already present. Any new install requires audit + blocking checkpoint |

</threat_model>
