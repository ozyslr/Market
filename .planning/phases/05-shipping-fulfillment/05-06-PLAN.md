<!-- Backend route contracts from Plan 04. -->

POST /api/orders/:orderSetId/subOrders/:subOrderId/return-request
Body: { reason: ReturnReason, notes?: string }
Response 201: { returnId: string }
Response 409: { error: 'return_window_expired' } | { error: 'not_delivered' }
Response 403: { error: 'forbidden' }
Auth: Firebase ID token in Authorization: Bearer header

POST /api/returns/:returnId/approve
Body: {} (empty — server reads return doc for context)
Response 200: { returnId, returnTrackingNumber, status: 'refunded' }
Auth: Firebase ID token (seller or admin)

POST /api/returns/:returnId/reject
Body: { rejectionReason: string }
Response 200: { returnId, status: 'rejected' }
Auth: Firebase ID token (seller or admin)

Firestore collection: returns/{returnId}
Fields: id, orderSetId, subOrderId, buyerId, sellerId, reason, notes?, status,
returnTrackingNumber?, returnLabelUrl?, approvedBy?, rejectionReason?,
refundId?, createdAt, updatedAt, windowExpiresAt

From src/types/returns.ts (after Plan 01):
ReturnReason = 'wrong_item'|'damaged'|'not_as_described'|'changed_mind'|'other'
ReturnStatus = 'pending'|'approved'|'rejected'|'label_sent'|'received'|'refunded'

## Trust Boundaries

| Boundary                                            | Description                                                |
| --------------------------------------------------- | ---------------------------------------------------------- |
| Buyer browser → POST /api/orders/.../return-request | Authenticated; buyer ownership enforced server-side        |
| Seller browser → POST /api/returns/:id/approve      | Authenticated; seller ownership enforced server-side       |
| Buyer browser → Firestore returns collection (read) | Firestore rules allow buyer to read only their own returns |

## STRIDE Threat Register

| Threat ID  | Category               | Component                                             | Disposition | Mitigation Plan                                                                                                                                                                                                                                       |
| ---------- | ---------------------- | ----------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-05-06-01 | Information Disclosure | Buyer reads another buyer's return doc                | mitigated   | Firestore rule in Task 1: match /returns/{returnId} allows read only if request.auth.uid == resource.data.buyerId OR resource.data.sellerId; isFullUser() guard blocks anonymous users; allow update, delete: if false prevents client-side tampering |
| T-05-06-02 | Tampering              | Buyer submits form with reason not in enum            | mitigate    | Server validates reason in Plan 04 route against ReturnReason values; invalid reason → 400                                                                                                                                                            |
| T-05-06-03 | Tampering              | Seller approves own return to fraudulently get refund | accept      | Seller cannot approve a return on a SubOrder they own unless they are also admin; sellerId check on returns doc                                                                                                                                       |
| T-05-06-04 | Elevation of Privilege | Buyer reads returnLabelUrl for another buyer's return | mitigate    | Firestore rules enforce buyerId match; returnLabelUrl only stored on the return doc, not on SubOrder                                                                                                                                                  |
| T-05-SC    | Tampering              | npm installs                                          | accept      | No new packages; firebase/firestore already in stack                                                                                                                                                                                                  |
