<!-- Backend route contracts from Plan 04. -->

POST /api/orders/:orderSetId/subOrders/:subOrderId/return-request
Body: { reason: ReturnReason, notes?: string }
Response 201: { returnId: string }
Response 409: { error: 'return_window_expired' } | { error: 'not_delivered' }
Response 403: { error: 'forbidden' }
Auth: Firebase ID token in Authorization: Bearer header

POST /api/returns/:returnId/approve
Body: {} (empty — server reads return doc for context)
Response 200: { returnId, returnTrackingNumber, status: 'refunded' }
Auth: Firebase ID token (seller or admin)

POST /api/returns/:returnId/reject
Body: { rejectionReason: string }
Response 200: { returnId, status: 'rejected' }
Auth: Firebase ID token (seller or admin)

Firestore collection: returns/{returnId}
Fields: id, orderSetId, subOrderId, buyerId, sellerId, reason, notes?, status,
returnTrackingNumber?, returnLabelUrl?, approvedBy?, rejectionReason?,
refundId?, createdAt, updatedAt, windowExpiresAt

## Trust Boundaries

| Boundary                                            | Description                                                |
| --------------------------------------------------- | ---------------------------------------------------------- |
| Buyer browser → POST /api/orders/.../return-request | Authenticated; buyer ownership enforced server-side        |
| Seller browser → POST /api/returns/:id/approve      | Authenticated; seller ownership enforced server-side       |
| Buyer browser → Firestore returns collection (read) | Firestore rules must allow buyer to read their own returns |

| ---------- | ---------------------- | ----------------------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-05-06-01 | Information Disclosure | Buyer reads another buyer's return doc                | mitigate    | Firestore rules: returns/{id} readable if request.auth.uid == resource.data.buyerId OR request.auth.uid == resource.data.sellerId OR isAdmin(); note: rules update for returns collection needed (not in this plan's files_modified — add to Firestore rules in a follow-up or verify existing rules cover it) |
| T-05-06-02 | Tampering              | Buyer submits form with reason not in enum            | mitigate    | Server validates reason in Plan 04 route against ReturnReason values; invalid reason → 400                                                                                                                                                                                                                     |
