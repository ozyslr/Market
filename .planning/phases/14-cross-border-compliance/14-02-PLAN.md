# Plan 14-02: Invoice Generation & GPSR Compliance

**Objective:** Generate proforma/commercial invoice PDFs for international orders and add EU GPSR compliance fields to the product form and detail page.

**Requirements:** CROSS-04, CROSS-05

## Tasks

### Task 1: International Invoice PDF Generation

<objective>
Generate a proforma/commercial invoice PDF for international orders containing: seller info, buyer info, HS codes, product values, shipping cost, and total declared value.
</objective>

<read_first>

- server/routes/stripe.ts (order data structure after payment)
- server/routes/orders.ts (order routes)
- pdfkit or html-pdf (should be installed via npm)
  </read_first>

<action>
1. Install `pdfkit` npm package (already may be planned).
2. Create `server/services/invoiceService.ts`:
   - `generateCommercialInvoice(order: OrderData): Promise<Buffer>` — returns PDF buffer
   - Invoice layout:
     - Header: "COMMERCIAL INVOICE / TİCARİ FATURA" bilingual
     - Seller: name, address, tax ID, Stripe Connect info
     - Buyer: name, shipping address, country
     - Items table: description, HS code, quantity, unit price, total
     - Totals: subtotal + shipping + VAT → total declared value
     - Footer: date, invoice number, "Country of Origin: Türkiye"
   - `generateProformaInvoice(order: OrderData): Promise<Buffer>` — same layout, "PROFORMA INVOICE" header
3. Add endpoint `GET /api/orders/:id/invoice` — returns PDF invoice (requires auth)
4. Add "Download Invoice" button to OrderDetail page for orders shipping internationally.
</action>

<acceptance_criteria>

- `pdfkit` in package.json
- generateCommercialInvoice returns a PDF Buffer
- Invoice PDF includes: seller info, buyer info, HS codes, item values, total
- Bilingual header (EN/TR)
- GET /api/orders/:id/invoice returns PDF with proper Content-Type
- `tsc --noEmit` passes
  </acceptance_criteria>

### Task 2: EU GPSR Compliance Fields

<objective>
Add GPSR (General Product Safety Regulation) compliance fields to the product form: EU authorized representative info and safety documentation upload.
</objective>

<read_first>

- src/components/seller/ProductForm.tsx (existing form fields)
- src/services/complianceService.ts (created in 14-01)
- src/types.ts (Product type)
  </read_first>

<action>
1. Add GPSR fields to ProductFormData (if not already present):
   - `gpsrRepName: string` — EU authorized representative name
   - `gpsrRepAddress: string` — EU authorized representative address
   - `gpsrRepEmail: string` — EU authorized representative email
   - `gpsrSafetyDoc: string` — URL to safety documentation PDF
   - `gpsrDeclarationDate: string` — date of declaration
2. Add a "GPSR Compliance" section in ProductForm (collapsible, near the bottom):
   - Info text: "AB'de satış için GPSR uyumluluğu zorunludur. Yetkili temsilci bilgilerinizi girin."
   - Fields for rep name, address, email
   - File upload for safety documentation PDF
   - Date picker for declaration date
3. On ProductDetail page:
   - If GPSR fields are filled: show green "GPSR Compliant" badge with tooltip showing rep info
   - If GPSR fields are empty: show amber "GPSR Pending" badge (EU buyers see this)
4. Update complianceService to check GPSR status:
   - `isGpsrCompliant(product): boolean`
   - `getGpsrInfo(product): GPSRInfo | null`
</action>

<acceptance_criteria>

- ProductForm has GPSR fields: rep name, address, email, safety doc upload, declaration date
- ProductDetail shows GPSR compliance badge (green if compliant, amber if pending)
- complianceService exports isGpsrCompliant and getGpsrInfo
- GPSR section is collapsible in ProductForm
- `tsc --noEmit` passes
  </acceptance_criteria>
