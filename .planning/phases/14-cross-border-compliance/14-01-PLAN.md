# Plan 14-01: HS Codes, Stripe Tax & Product Eligibility

**Objective:** Assign HS codes per product category, enable Stripe Tax for automatic VAT, and block ineligible products at checkout by destination country.

**Requirements:** CROSS-01, CROSS-02, CROSS-03

## Tasks

### Task 1: HS Code System & Product Form Integration

<objective>
Create an HS (Harmonized System) code lookup table keyed by category, and add HS code field to the product form with auto-suggestion from category.
</objective>

<read_first>

- src/components/seller/ProductForm.tsx (hsCode field already exists in ProductFormData)
- src/data/hsCodes.ts (if it exists, or create)
- src/types.ts (Product type definition)
  </read_first>

<action>
1. Create `src/data/hsCodes.ts`: HS code master data as a constant object keyed by categoryId.
   - Include top-level HS codes for common e-commerce categories:
     - Electronics: 8471 (computers), 8517 (phones), 8518 (headphones)
     - Clothing: 6109 (t-shirts), 6204 (dresses), 6110 (sweaters)
     - Home/Garden: 9403 (furniture), 9405 (lighting), 6911 (ceramics)
     - Jewelry: 7117 (costume), 7113 (precious metal)
     - Food: 2106 (food preparations), 1905 (baked goods)
     - Art/Craft: 9701 (paintings), 9703 (sculptures)
     - Default: 6117 (other made-up textile articles)
   - Export a function `getHsCode(categoryId: string): string` that returns the HS code.
   - Export `HS_CODE_LABELS: Record<string, string>` with human-readable descriptions.
2. Update ProductForm.tsx hsCode field:
   - Auto-fill hsCode when category changes (call getHsCode)
   - Show HS code description label next to the code input
   - Allow seller to override manually
3. Display HS code on ProductDetail page (below shipping info, small text: "HS Code: 8471.30").
</action>

<acceptance_criteria>

- HS code auto-filled when category is selected in ProductForm
- Seller can manually override HS code
- HS_CODE_LABELS maps codes to descriptions
- ProductDetail shows HS code from product data
- `tsc --noEmit` passes
  </acceptance_criteria>

### Task 2: Stripe Tax Auto-VAT Configuration

<objective>
Enable Stripe Tax automatic VAT calculation on checkout based on buyer location, and update Stripe PaymentIntent to include tax.
</objective>

<read_first>

- server/routes/stripe.ts (PaymentIntent creation — already modified in Phase 13)
- .env.example (Stripe keys)
  </read_first>

<action>
1. In Stripe Dashboard: enable Stripe Tax (manual step — document in plan output).
2. Update `server/routes/stripe.ts` PaymentIntent creation:
   - Add `automatic_tax: { enabled: true }` to PaymentIntent params when buyer country is in EU
   - Pass buyer's country code from request body (`buyerCountry: string`)
   - Add `metadata.buyerCountry` to PaymentIntent for reconciliation
3. Update `src/pages/Checkout.tsx`:
   - Send buyer's shipping country to the create-payment-intent API call
   - Show estimated VAT line item in order summary when available
4. Add env docs: `STRIPE_TAX_ENABLED=true` to .env.example
</action>

<acceptance_criteria>

- PaymentIntent includes `automatic_tax: { enabled: true }` for EU buyers
- Buyer country passed from Checkout to Stripe API
- Stripe Tax calculates correct VAT rate per buyer country
- `tsc --noEmit` passes
  </acceptance_criteria>

### Task 3: Product Eligibility by Destination Country

<objective>
Block products that cannot be shipped to the buyer's country at checkout, and show clear messaging about restrictions.
</objective>

<read_first>

- src/pages/Checkout.tsx (product eligibility check)
- src/services/complianceService.ts (create if needed)
  </read_first>

<action>
1. Create `src/services/complianceService.ts`:
   - `isProductEligible(productId, destinationCountry): Promise<boolean>` — checks product restrictions
   - `getRestrictionReason(productId, destinationCountry): string` — returns reason (e.g., "Bu ürün gıda içeriyor ve gümrük kısıtlaması nedeniyle Almanya'ya gönderilemez")
   - Restriction rules (hardcoded for MVP):
     - Food/alcohol → restricted to most non-EU countries
     - Cosmetics → restricted if no GPSR doc
     - Electronics → require CE marking for EU
2. In Checkout.tsx:
   - Call isProductEligible for each cart item
   - If any item ineligible: show warning card with product name + restriction reason
   - Block checkout button: "Sepetinizde gönderilemeyen ürünler var. Lütfen çıkarın."
</action>

<acceptance_criteria>

- complianceService exports isProductEligible and getRestrictionReason
- Checkout checks product eligibility by destination country
- Ineligible products show restriction reason in cart/checkout
- Checkout blocked when cart contains ineligible items
- `tsc --noEmit` passes
  </acceptance_criteria>
