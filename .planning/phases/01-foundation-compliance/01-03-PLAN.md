<threat_model>

## Trust Boundaries

| Boundary                      | Description                                                  |
| ----------------------------- | ------------------------------------------------------------ |
| client -> consent storage     | localStorage consent preferences (client-side)               |
| client -> deletion API        | User submits identity data for deletion request              |
| admin -> anonymization        | Admin approves deletion, triggering irreversible PII removal |
| browser -> third-party pixels | GA4/Meta/TikTok scripts load only after explicit consent     |

## STRIDE Threat Register

| Threat ID | Category               | Component                  | Disposition | Mitigation Plan                                                                                                                |
| --------- | ---------------------- | -------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------ |
| T-01-011  | Information Disclosure | third-party pixels         | mitigate    | 3-tier consent: pixels only fire when marketing consent = accepted. initAnalytics checks consent level before loading scripts. |
| T-01-012  | Tampering              | consent preferences        | accept      | localStorage can be modified by user; consent is a user preference, not an integrity concern                                   |
| T-01-013  | Repudiation            | data deletion audit        | mitigate    | deletion requests stored in Firestore with status history and processedAt timestamps                                           |
| T-01-014  | Spoofing               | deletion request ownership | mitigate    | verifyFirebaseToken on POST /api/compliance/deletion-request ensures only the authenticated user submits for their own account |
| T-01-015  | Elevation of Privilege | unauthorized data access   | mitigate    | verifyAdmin on all admin deletion endpoints; Firestore rules block non-admin reads on dataDeletionRequests                     |

</threat_model>
