<threat_model>

## Trust Boundaries

| Boundary              | Description                                                   |
| --------------------- | ------------------------------------------------------------- |
| client -> API         | Untrusted input crosses from browser to Express route handler |
| Express -> Firestore  | Server-side writes use admin SDK (bypasses security rules)    |
| User -> OrderSet data | Buyer reads only own orders; seller reads none in Phase 1     |

## STRIDE Threat Register

| Threat ID | Category               | Component               | Disposition | Mitigation Plan                                                                                          |
| --------- | ---------------------- | ----------------------- | ----------- | -------------------------------------------------------------------------------------------------------- |
| T-01-001  | Spoofing               | POST /api/orders/create | mitigate    | verifyFirebaseToken middleware rejects unauthenticated requests                                          |
| T-01-002  | Tampering              | order creation body     | mitigate    | Zod validation on items array, currency, shippingAddress fields                                          |
| T-01-003  | Repudiation            | state transitions       | mitigate    | optimistic concurrency (version field) prevents lost updates; every transition is a new document version |
| T-01-004  | Information Disclosure | GET /api/orders/:id     | mitigate    | ownership check (req.uid vs orderSet.userId) prevents reading others' orders                             |
| T-01-005  | Elevation of Privilege | direct Firestore write  | mitigate    | security rules block client-side writes to orderSets/subOrders; only admin SDK (server) can write        |
| T-01-SC   | Tampering              | npm packages            | mitigate    | slopcheck + human verify for new packages (none expected; all deps already installed)                    |

</threat_model>
