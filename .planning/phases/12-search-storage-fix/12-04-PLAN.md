# Plan 12-04: Search Analytics Dashboard

**Objective:** Track and display search analytics in the Admin panel: top search queries, no-results queries, click-through rate, and search volume trends.

**Requirements:** SRC-05

## Tasks

### Task 1: Record Search Events

<objective>
Record search query events and click-through events to Firestore for analytics processing. Capture: query text, result count, zero-results flag, clicked product ID, language, and timestamp.
</objective>

<read_first>

- src/services/analyticsService.ts (existing analytics event patterns — trackFunnelEvent, event structure)
- src/services/typesenseService.ts (searchProducts function — where queries execute)
- src/components/search/SearchResults.tsx (where clicks happen — created in 12-03)
  </read_first>

<action>
1. Create search event types in analyticsService.ts:
   - `SEARCH_QUERY` — fired on each search: { query, resultCount, zeroResults: boolean, language, filters: { category?, brand?, priceRange?, rating? }, timestamp }
   - `SEARCH_CLICK` — fired on result click: { query, productId, position (1-based index), productTitle, timestamp }
   - `SEARCH_NO_RESULTS` — fired when zero results: { query, language, filters, timestamp }
2. Add `recordSearchEvent(eventType, data)` function to analyticsService.ts:
   - Write to Firestore `searchEvents` collection (new collection)
   - Fire-and-forget pattern (don't block search on analytics write)
   - Batch writes if multiple events fire in rapid succession
3. Wire event recording in search components:
   - SearchBar: fire SEARCH_QUERY on each search execution
   - SearchResults: fire SEARCH_CLICK when a product result is clicked
   - TypesenseService or SearchResults: fire SEARCH_NO_RESULTS when result count is 0
4. Add search event types to the existing analytics event type union if one exists.
</action>

<acceptance_criteria>

- `searchEvents` Firestore collection receives documents with event type, query, resultCount, timestamp
- SEARCH_QUERY event fires on each search execution
- SEARCH_CLICK event fires on product result click with productId and position
- SEARCH_NO_RESULTS event fires when zero results
- Analytics writes are fire-and-forget (don't block search response)
- `tsc --noEmit` passes
  </acceptance_criteria>

### Task 2: Build Search Analytics Dashboard

<objective>
Add a "Search Analytics" section to the Admin Analytics page showing: top queries, no-results queries, click-through rate, query volume over time, and search-to-purchase conversion.
</objective>

<read_first>

- src/pages/AdminAnalytics.tsx (existing analytics page — funnel conversion card pattern)
- src/services/analyticsService.ts (just updated in Task 1)
- src/services/typesenseService.ts (for index status)
  </read_first>

<action>
1. Create a "Search Analytics" section card in AdminAnalytics.tsx with sub-cards:
   - **Top Queries (last 30 days):** Table with columns: Query, Count, Avg Results, CTR%. Sortable by count. Top 20.
   - **No-Results Queries:** Table with columns: Query, Count, Last Searched. Highlight in red/amber. Top 20.
   - **Query Volume (last 7 days):** Line chart (Recharts) — queries per day.
   - **Click-Through Rate:** Gauge or percentage card — overall CTR% (clicks/queries).
   - **Zero-Results Rate:** Percentage — queries with 0 results / total queries.
2. Create a `getSearchAnalytics(days)` function in analyticsService.ts:
   - Aggregates from `searchEvents` collection
   - Groups by query text, counts occurrences
   - Computes CTR per query (clicks / impressions)
   - Returns structured data for chart rendering
3. Add date range selector to filter analytics by: Last 7 days, Last 30 days, Last 90 days.
4. Add "No-Results Queries" action: admin can click a query to add it as a synonym or create a product for it (quick-action buttons).
</action>

<acceptance_criteria>

- Admin Analytics page has "Search Analytics" card
- Top Queries table shows top 20 queries with count, avg results, CTR
- No-Results Queries table highlighted in red/amber
- Query Volume line chart renders with Recharts
- CTR% and Zero-Results Rate percentage cards shown
- Date range selector: 7d, 30d, 90d
- No-results queries have quick-action buttons for admin
- `tsc --noEmit` passes
  </acceptance_criteria>
