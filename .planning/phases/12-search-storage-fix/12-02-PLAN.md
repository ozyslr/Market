# Plan 12-02: Typesense Setup & Firestore Sync

**Objective:** Install and configure Typesense, create per-language search collections, and set up real-time Firestore-to-Typesense sync via onWrite webhook triggers.

**Requirements:** SRC-01, SRC-03, SRC-04

## Tasks

### Task 1: Install Typesense and Create Service

<objective>
Install the typesense npm package, create a TypesenseService for client operations, and register a sync webhook route on the Express server.
</objective>

<read_first>

- package.json (current dependencies)
- server.ts (route registration pattern)
- src/services/ (existing service patterns — read any service like productService.ts for Firestore initialization pattern)
  </read_first>

<action>
1. Install `typesense` npm package (latest 3.x): add to package.json dependencies.
2. Create `src/services/typesenseService.ts`:
   - Initialize Typesense client with config from env vars:
     - `TYPESENSE_API_KEY` (admin key for server, search-only key for client)
     - `TYPESENSE_HOST` (default: `localhost` for self-hosted, or cloud URL)
     - `TYPESENSE_PORT` (default: `8108`)
     - `TYPESENSE_PROTOCOL` (default: `https`)
   - Export `searchProducts(query, filters, language)` function — uses Typesense `multi_search` or collection-specific search
   - Export `upsertProduct(product)` function — transforms Firestore product doc to Typesense document
   - Export `deleteProduct(productId)` function
   - Export `initializeCollections()` — creates per-language collections if not exist
3. Create `server/routes/typesenseSync.ts`:
   - POST `/api/typesense/sync/product` — receives product data, upserts to Typesense
   - DELETE `/api/typesense/sync/product/:id` — deletes from Typesense
   - POST `/api/typesense/sync/reindex` — triggers full re-index (admin only)
   - Each endpoint verifies a shared secret (`TYPESENSE_SYNC_SECRET` header)
4. Register the sync route in server.ts following the existing route registration pattern.
5. Add env vars to `.env.example` (TYPESENSE_API_KEY, TYPESENSE_HOST, TYPESENSE_PORT, TYPESENSE_PROTOCOL, TYPESENSE_SYNC_SECRET).
</action>

<acceptance_criteria>

- `typesense` appears in package.json dependencies
- `src/services/typesenseService.ts` exports searchProducts, upsertProduct, deleteProduct, initializeCollections
- `server/routes/typesenseSync.ts` has POST /api/typesense/sync/product, DELETE /api/typesense/sync/product/:id, POST /api/typesense/sync/reindex
- Sync endpoints validate TYPESENSE_SYNC_SECRET header
- New route is registered in server.ts
- `.env.example` contains TYPESENSE_API_KEY, TYPESENSE_HOST, TYPESENSE_PORT, TYPESENSE_PROTOCOL, TYPESENSE_SYNC_SECRET
- `tsc --noEmit` passes
  </acceptance_criteria>

### Task 2: Create Bootstrap Script and Firestore Sync Triggers

<objective>
Create a bootstrap script for initial Typesense indexing and wire up Firestore onWrite triggers for real-time sync.
</objective>

<read_first>

- src/services/typesenseService.ts (just created in Task 1)
- src/services/productService.ts (product fields and structure)
- scripts/bootstrap-admin-claims.mjs (existing bootstrap script pattern for reference)
  </read_first>

<action>
1. Create `scripts/bootstrap-typesense.mjs`:
   - Imports typesenseService and Firestore admin
   - Reads all products from Firestore `products` collection with cursor pagination (batch size: 500)
   - Transforms each product to Typesense document format (id, title, description, price, categoryId, brand, rating, imageUrl, storeId, language, tags, createdAt)
   - Upserts each product to the appropriate language collection (products_tr, products_en, products_de, products_ar)
   - Shows progress: "Indexed 500/10000 products..."
   - Reports completion: "Bootstrap complete: N products indexed in M minutes"
2. Create Typesense collection schemas in typesenseService.ts (initializeCollections):
   - Collection `products_tr` with Turkish locale analyzer
   - Collection `products_en` with English locale analyzer
   - Collection `products_de` with German locale analyzer
   - Collection `products_ar` with Arabic locale analyzer (RTL support)
   - Each collection: fields for title (string), description (string), price (float), categoryId (string), brand (string), rating (float), imageUrl (string), storeId (string), language (string), tags (string[]), createdAt (int64)
   - Default sorting field: `createdAt`
   - Facet fields: `categoryId`, `brand`, `rating`, `price`
3. Add sync webhook caller in productService.ts (or create a sync trigger service):
   - After product create/update/delete operations, call the Typesense sync webhook
   - Use `fetch()` with TYPESENSE_SYNC_SECRET header
   - Fire-and-forget pattern (don't block the response on sync completion)
   - Add retry logic: if sync call fails, log error but don't fail the product operation
</action>

<acceptance_criteria>

- `scripts/bootstrap-typesense.mjs` reads all products with pagination (batch 500)
- Bootstrap script shows progress during indexing
- `initializeCollections()` creates 4 per-language collections with correct analyzers
- Each collection has facet fields: categoryId, brand, rating, price
- productService.ts has fire-and-forget sync calls after create/update/delete
- Sync calls use TYPESENSE_SYNC_SECRET from env
- Product operations don't fail if sync call fails (fire-and-forget)
- `tsc --noEmit` passes
  </acceptance_criteria>
