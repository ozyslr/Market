# Plan 12-01: Firebase Storage Seller Upload Fix

**Objective:** Fix Firebase Storage permissions so sellers can upload product images without permission errors. Add clear error messaging for upload failures.

**Requirements:** BUG-01, BUG-02

## Tasks

### Task 1: Fix Firebase Storage Rules

<objective>
Update Firebase Storage security rules to allow authenticated sellers to upload product images to their own directory.
</objective>

<read_first>

- storage.rules (or firebase.storage.rules)
- firebase.json (storage rules config)
- src/services/productService.ts (upload paths used)
  </read_first>

<action>
1. Open the Firebase Storage rules file (storage.rules at project root).
2. Add a rule allowing write to `products/{userId}/**` when:
   - `request.auth != null` (authenticated)
   - `request.auth.uid == userId` (owns the path)
   - `request.resource.size < 10 * 1024 * 1024` (max 10MB)
   - `request.resource.contentType.matches('image/.*')` (images only)
3. Ensure existing read rules (public read for product images) remain unchanged.
4. Deploy via `firebase deploy --only storage` (or note the deploy command).
5. Verify no other storage paths are accidentally opened — only `products/{userId}/**` should have the new write rule.
</action>

<acceptance_criteria>

- `storage.rules` file contains `match /products/{userId}/{allPaths=**}` block with write conditions
- Write rule checks `request.auth.uid == userId`
- Write rule checks `request.resource.size < 10 * 1024 * 1024`
- Write rule checks `request.resource.contentType.matches('image/.*')`
- Public read for product images still exists (no read restrictions added)
- `firebase deploy --only storage` succeeds OR deploy command is documented in plan output
  </acceptance_criteria>

### Task 2: Add Upload Error Messaging in ProductForm

<objective>
Catch Firebase Storage upload errors in the product image upload flow and display clear, user-readable error messages instead of silent failures.
</objective>

<read_first>

- src/components/seller/ProductForm.tsx (existing upload logic)
- src/services/productService.ts (upload service function)
  </read_first>

<action>
1. In ProductForm.tsx, find the image upload handler (where Firebase Storage upload is called).
2. Wrap the upload call in try/catch. On catch, extract the Firebase Storage error code:
   - `storage/unauthorized` → "Resim yükleme izniniz yok. Lütfen tekrar giriş yapın."
   - `storage/canceled` → "Yükleme iptal edildi."
   - `storage/retry-limit-exceeded` → "Yükleme zaman aşımına uğradı. Lütfen tekrar deneyin."
   - `storage/quota-exceeded` → "Depolama limiti aşıldı."
   - Default → error.message or "Resim yüklenirken bir hata oluştu. Lütfen tekrar deneyin."
3. Display the error message in a visible toast or inline error under the image upload area.
4. Keep the partially uploaded files visible (don't clear the selection on error).
5. Add a retry button next to the error message.
</action>

<acceptance_criteria>

- Upload failure shows a visible error message (toast or inline text) — not just console.error
- Error messages are in Turkish (TR) matching the app's default language
- Error message types: unauthorized, canceled, timeout, quota-exceeded, and generic fallback
- Existing selected files remain visible after upload error (not cleared)
- Retry button appears next to error message
- `tsc --noEmit` passes
  </acceptance_criteria>
