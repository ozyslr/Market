Accent (`--accent`) is reserved for:

- Primary CTA buttons (Submit Application, Approve, Create API Key, Import CSV)

- Active tab underline in SellerImportCenter tabs
- "View document" signed-URL link text

Do NOT use accent for status badges (use semantic colors: green/amber/red), informational text, or decorative elements.

## Surface Inventory

Six UI surfaces this phase must define contracts for:

### Surface 1: KYC Onboarding Multi-Step Form (SellerApplication.tsx hardening)

**Step structure:** 3 steps (existing step state machine kept, step 3 extended)

- Step 1: Store info (store name, origin/country, phone, tax ID)
- Step 2: Business details (categories, experience, monthly target)
- Step 3: Document upload + Stripe Identity verification

**Step indicator:**

- Horizontal row of numbered circles at top of form card
- Active step: accent-filled circle, white numeral, 24px diameter
- Completed step: green-filled circle, checkmark icon, 24px diameter
- Upcoming step: gray-200 border circle, gray numeral, 24px diameter
- Connecting line between circles: 1px gray-200; completed segment fills accent
- Label below each circle: 12px / weight 500 / gray-600; active label uses accent color

**Document upload component (3 instances: identity, tax_certificate, bank_iban):**

Each doc slot is a self-contained card (white bg, border gray-200, rounded-lg, padding 16px) with 4 states:

| State     | Visual                                                                                                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty     | Dashed border (border-dashed border-gray-300), upload icon (lucide `Upload`, 24px, gray-400), label "{doc type} — click or drag to upload", 14px muted text. Min height 120px.                        |
| Uploading | Spinner (`Loader2`, animate-spin, 20px, accent), "Uploading…" label, dashed border → solid accent border. Progress bar (thin, 4px, accent fill, full width, rounded) below card.                      |
| Uploaded  | Solid border green-500, checkmark icon (`CheckCircle`, 20px, green-600), filename truncated to 28 chars + extension, file size in muted text, small "Replace" link (12px, gray-500, hover underline). |
| Error     | Solid border red-500, alert icon (`AlertCircle`, 20px, red-500), error message below icon (14px, red-600).                                                                                            |

**3-doc gate UI:** "Submit Application" button is `disabled` and shows `opacity-50 cursor-not-allowed` until all 3 doc slots show Uploaded state. Tooltip on hover: "Upload all 3 required documents to continue".

**Stripe Identity step (after all 3 docs uploaded):**

- New card below doc uploads: "Identity Verification" section
- States:
  - Not started: info box (accent-soft bg, accent border-l-4), text "We'll verify your identity via Stripe. Takes 2-3 minutes. You'll need your ID and a selfie." + "Start Verification" button (accent, full-width on mobile)
  - Redirecting: spinner + "Opening Stripe verification…"
  - Pending webhook: amber badge "Identity check in progress — we'll notify you"
  - Verified: green badge "Identity verified" + `CheckCircle` icon
  - Requires input: red badge "Verification needs attention" + retry button

**Post-submit pending state:**

- Replace form with centered success card: `CheckCircle` icon (48px, green-500), heading "Application Submitted", body "Your application is under review. We'll email you when a decision is made. This typically takes 1-2 business days.", back-to-home link.

**EU Stripe Connect handoff state (shown in seller dashboard after approval, not in application flow):**

- Banner at top of SellerLayout: amber bg, "Complete your payment account setup to start selling." + "Continue Setup" button → generates fresh AccountLink on click → external redirect to Stripe hosted onboarding.
- After `payouts_enabled` webhook: banner replaced with green "Payment account active — you can now list products."

### Surface 2: Admin KYC Review Panel (AdminSellers.tsx + AdminSellerView.tsx hardening)

**AdminSellers list view:**

- Table with columns: Seller name, Store name, Origin (TR/EU flag badge), Submitted date, Status badge, Action link
- Status badges: `pending` → amber pill, `approved` → green pill, `rejected` → red pill, `identity_verified` → blue pill
- Filter tabs above table: All / Pending / Approved / Rejected — active tab uses accent underline

**AdminSellerView detail view:**

_Document viewer section:_

- 3 document cards side by side (3-col grid on desktop, 1-col on mobile)
- Each card: doc type label (weight 600), "View Document" button (outline style, accent border + text, 14px)
- On "View Document" click: button shows `Loader2` spinner while fetching signed URL, then opens URL in new tab (target="\_blank", rel="noopener noreferrer")
- Signed URL TTL: 5 minutes — if fetch fails show: "Document link expired. Click to refresh." (amber inline alert)
- NEVER display raw Storage paths or document URLs in the DOM

_Stripe Identity result display:_

- Status row: label "Identity Verification", value badge matching state (verified=green, requires_input=amber/red, pending=gray)
- If `requires_input`: show `vs.last_error.reason` in muted 13px text below badge

_Payment provisioning status row:_

- Label "Payment Account", then:
  - TR seller: "Iyzico sub-merchant" + status badge (pending/active)
  - EU seller: "Stripe Connect Express" + status badge (pending/onboarding/active) + "Copy Onboarding Link" button if status is onboarding

_Approve / Reject actions:_

- "Approve" button: accent fill, `CheckCircle` icon left, disabled + `opacity-50` if not all 3 docs present OR identity not verified
- "Reject" button: destructive (--color-mercora-red fill), `XCircle` icon left
- Reject flow: clicking Reject opens inline form below buttons (NOT a modal) — textarea "Reason for rejection" (required, min 10 chars), red "Confirm Rejection" button + gray "Cancel" link. Submitting without reason shows field-level error "Please provide a rejection reason".
- After approve: success toast (green, top-right, 4s) "Seller approved. Payment account provisioning initiated."
- After reject: success toast (red, top-right, 4s) "Application rejected. Seller notified."

### Surface 3: Seller Store Page (SellerStore.tsx hardening)

**Public store URL:** `/store/{slug}` — slug displayed in store management as copyable text field with copy-to-clipboard button (`Copy` lucide icon, 16px). Success: icon swaps to `Check` for 2s.

**Store management form sections:**

- Logo upload: circular 80px preview (object-cover, rounded-full, border-2 accent), "Change Logo" overlay on hover (semi-transparent black, white camera icon)
- Banner upload: 16:4 aspect ratio preview (w-full, h-24 on mobile / h-32 on desktop), "Change Banner" hover overlay
- About/description: textarea, 4 rows, max 500 chars, character counter bottom-right (muted, "N / 500")
- "Save Changes" button: accent fill, full-width on mobile, right-aligned on desktop

**RTL layout for AR locale:** all cards use `dir` attribute matching current language. Text alignment flips. Lucide icons are direction-neutral. Flex rows use `flex-row-reverse` when `dir="rtl"` OR use `gap-x` + `me-`/`ms-` logical margin utilities.

### Surface 4: Seller Product Management (SellerInventory.tsx hardening)

**Inline validation states:**

| Field          | Invalid state                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| Images (min 1) | Red border on image grid container, "At least 1 product photo is required" text in red-600 14px below |
| Category       | Red border on select, "Please select a category" below                                                |
| Price          | Red border if 0 or empty, "Enter a valid price" below                                                 |
| Stock          | Red border if negative, "Stock cannot be negative" below                                              |

- Client validation: on form submit attempt (not on every keystroke)
- Server validation error display: if server returns 400, show error banner at top of form (red-50 bg, red-600 border-l-4, red-700 text, `AlertCircle` icon + message text)

**Product table empty state:**

- Centered illustration area (gray-100 rounded-xl, 160px height), `Package` lucide icon (48px, gray-300), "No products yet", "Add your first product to start selling." body, "Add Product" button (accent fill)

### Surface 5: CSV Import Center (SellerImportCenter.tsx hardening)

**Upload zone:**

- Dashed border dropzone (border-2 border-dashed border-gray-300, rounded-xl, p-8 center), `FileUp` icon (32px, gray-400), "Drop your CSV here or click to browse", "Max 10 MB, UTF-8 encoded" muted helper
- Drag-over state: accent border, accent-soft background
- File selected (pre-import): show filename + size chip (gray-100 pill, `FileText` icon 14px, filename, size), "Import" button activates

**Import result UI (after server responds):**

Success/partial banner — always shown after import completes:

```
[CheckCircle green 20px]  Import complete
                          92 products imported / 8 rows skipped
                          [Download Error Report]  ← only if errors > 0
```

- Banner bg: green-50, border green-200, green-800 text for "Import complete"
- If all rows failed: red-50 bg, `XCircle` red icon, "Import failed — 0 products imported / N rows had errors"
- "Download Error Report" button: outline style (gray border, gray-700 text), `Download` lucide icon left, 14px
- Error report filename: `import-errors-{YYYY-MM-DD}.csv`

**Error report columns (CSV):** `row`, `field`, `reason` — 3 columns, UTF-8 BOM, comma-separated

**Import progress state (while server processes):**

- Replace "Import" button with spinner + "Importing… please wait"
- Thin progress bar below dropzone (indeterminate, accent fill, animate-pulse)

**Export action:**

- "Export Products" button: outline style, `Download` icon, positioned top-right of the CSV tab content area

**Tab active state:** accent underline (2px solid --accent), active tab label in accent color. Inactive tabs: gray-600 text, no underline.

### Surface 6: Seller API Keys (SellerApiKeys.tsx — minimal UI hardening)

**Key list table columns:** Key name, Prefix (first 8 chars + "…"), Permissions (comma-separated scope pills), Created, Last used, Actions (Revoke)

**Permission scope pills:** gray-100 bg, gray-700 text, 12px, rounded, px-2 py-0.5. One pill per scope.

**Rate limit info row:** below the keys table, gray-50 card, `Info` lucide icon (14px, gray-400), "API requests are limited to 100/minute per key. Limits reset every 60 seconds." — 13px muted text.

**Create key flow:**

- "Create API Key" button: accent fill, `Plus` icon left
- Inline form expands below button (not modal): key name input, checkbox grid for permissions
- After creation: key value shown ONCE in a highlighted box (yellow-50 bg, amber border, monospace 13px font), "Copy Key" button, warning "This key will not be shown again. Copy it now."
- After copy confirmation or dismissal: key value hidden, replaced by masked display

**Revoke confirmation:**

- Inline destructive confirmation (not modal): "Revoke this key? This cannot be undone." + red "Revoke" button + "Cancel" link
- Revoked key row: strikethrough text, gray-400 color, removed from table after 2s (motion fade-out)

## Animation Contract

Source: existing codebase uses `motion` (framer-motion v12) via `motion/react`. Reduced-motion media query respected via global CSS in index.css.

| Element                                      | Animation                                                                    | Duration | Easing   |
| -------------------------------------------- | ---------------------------------------------------------------------------- | -------- | -------- |
| Step transition (KYC steps 1→2→3)            | `motion.div` with `initial={{opacity:0,x:20}}` → `animate={{opacity:1,x:0}}` | 200ms    | ease-out |
| Post-submit success card                     | `initial={{opacity:0,scale:0.95}}` → `animate={{opacity:1,scale:1}}`         | 250ms    | ease-out |
| Upload slot state change                     | `animate={{borderColor}}` transition                                         | 150ms    | ease     |
| Import result banner                         | `initial={{opacity:0,y:-8}}` → `animate={{opacity:1,y:0}}`                   | 200ms    | ease-out |
| Revoked key row fade-out                     | `exit={{opacity:0,height:0}}` with `AnimatePresence`                         | 300ms    | ease-in  |
| Toast notification                           | slide-in from top-right, `initial={{x:100,opacity:0}}`                       | 250ms    | ease-out |
| Inline expand (reject form, create key form) | `initial={{height:0,opacity:0}}` → `animate={{height:'auto',opacity:1}}`     | 200ms    | ease-out |

All animations respect `prefers-reduced-motion: reduce` — the global CSS sets `transition-duration: 0.01ms` when active.

## RTL / Multi-Language Requirements

- All 6 surfaces must work in TR, EN, DE, AR
- AR locale activates `dir="rtl"` on `<html>` tag (handled by LanguageContext)
- Use Tailwind logical property classes: `ms-` not `ml-`, `me-` not `mr-`, `ps-` not `pl-`, `pe-` not `pr-`, `text-start` not `text-left`
- Icons: lucide icons are symmetric; directional icons (`ArrowRight`, `ChevronRight`) must flip with CSS `[dir="rtl"] .icon-directional { transform: scaleX(-1) }` — add this to index.css
- Step indicator connecting line: use `flex-row` (flips to right-to-left in RTL naturally)
- Toast position: top-right in LTR, top-left in RTL
