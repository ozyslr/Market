## Phase Goal

**As a** seller, **I want to** complete identity verification and document upload, **so that** I can get approved and start selling on the platform with my regional payment account provisioned automatically.

<objective>
KYC onboarding pipeline: private document storage, Stripe Identity automated ID check, admin review panel with document viewer, and payment account provisioning (Iyzico TR / Stripe Connect EU) on approval.

Purpose: This is the phase's security-critical core — PII documents must never be publicly accessible, identity must be automatically pre-verified, and payment accounts must be provisioned idempotently only after admin approval.
Output: kycService.ts, StripeConnectProvider, storage.rules, extended sellerApplicationService, hardened SellerApplication.tsx (3-doc upload + Identity redirect), hardened AdminSellerView.tsx (signed URL viewer + provisioning trigger + approve/reject UI per UI-SPEC).
</objective>

## Trust Boundaries

| Boundary                                              | Description                                                        |
| ----------------------------------------------------- | ------------------------------------------------------------------ |
| Seller browser → POST /api/kyc/upload-url             | Seller-authenticated; sellerId in payload must equal req.uid       |
| Admin browser → GET /api/kyc/signed-url/\*            | Admin-only; verifyAdmin gate; signed URL expires in 5 min          |
| Admin browser → POST /api/admin/seller/:id/approve-tr | Admin-only; idempotency guard before Iyzico call                   |
| Admin browser → POST /api/admin/seller/:id/approve-eu | Admin-only; idempotency guard before Stripe account creation       |
| Stripe webhook → server                               | HMAC signature verified by existing stripe.webhooks.constructEvent |
| Firebase Storage client SDK → kyc/\*                  | Blocked by storage.rules (allow read,write: if false)              |
