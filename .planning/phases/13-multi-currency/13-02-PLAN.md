# Plan 13-02: Checkout Currency Integration

**Objective:** Implement 15-minute FX rate locking at checkout, Stripe presentment_currency for EUR payments, and Iyzico handling for TRY-only Turkish payments.

**Requirements:** CUR-04, CUR-05

## Tasks

### Task 1: FX Rate Lock at Checkout

<objective>
Lock the EUR/TRY exchange rate for 15 minutes when the buyer enters checkout, ensuring the displayed price matches the charged amount.
</objective>

<read_first>

- src/context/CurrencyContext.tsx (created in 13-01)
- src/context/CartContext.tsx (cart total calculation)
- src/pages/Checkout.tsx (checkout page structure)
  </read_first>

<action>
1. In CartContext or checkout flow, add `lockedRate` state:
   - `lockRate()` — stores `{ rate: number, expiresAt: timestamp }` in sessionStorage
   - `getLockedRate(): number | null` — returns rate if not expired (15 min window)
   - On checkout page entry: auto-lock the current rate
2. Display countdown timer in checkout: "Fiyat garantisi: 14:32 dakika" showing remaining lock time.
3. If lock expires while on checkout page:
   - Show warning: "Fiyat garantisi sona erdi. Kur yenilendi."
   - Auto-refresh the locked rate with the latest cached rate
4. Use `lockedRate` for all price displays on the checkout page (order summary, line items, total).
</action>

<acceptance_criteria>

- Rate locked in sessionStorage on checkout entry with 15-min expiry
- Countdown timer visible on checkout showing remaining lock time
- Expired lock shows warning message and auto-refreshes
- All prices on checkout use locked rate (not live rate)
- Lock persists across page refreshes within 15-min window
- `tsc --noEmit` passes
  </acceptance_criteria>

### Task 2: Stripe Presentment Currency + Iyzico Guard

<objective>
Configure Stripe PaymentIntent for EUR presentment_currency, ensure correct settlement, and guard Iyzico to TRY-only.
</objective>

<read_first>

- server/routes/stripe.ts (existing Stripe payment routes)
- server/routes/iyzico.ts (existing Iyzico routes)
- src/pages/Checkout.tsx (payment method selection)
- src/hooks/useOneClickCheckout.ts (saved card checkout)
  </read_first>

<action>
1. Update `server/routes/stripe.ts` — create-payment-intent handler:
   - Read `presentment_currency` from request body (EUR or TRY)
   - If EUR: set `currency: 'eur'` on PaymentIntent, enable `automatic_payment_methods`
   - If TRY: current behavior unchanged
   - Add `metadata.rate_locked` and `metadata.rate_value` to PaymentIntent for reconciliation
2. Update `server/routes/stripe.ts` — one-click-checkout:
   - Same presentment_currency handling for saved card payments
3. Guard Iyzico:
   - If active currency is EUR → show "Iyzico only supports TRY. Please switch to TRY or use credit card (Stripe)."
   - Iyzico payment option hidden/disabled when EUR selected
   - Seller payout always in TRY (settlement currency = TRY)
4. Seller Payout note: Add comment/doc that sellers always receive TRY payouts regardless of buyer currency — Stripe handles conversion to settlement currency automatically.
</action>

<acceptance_criteria>

- Stripe PaymentIntent includes `currency: 'eur'` when EUR selected
- Rate metadata (rate_locked, rate_value) appears on PaymentIntent
- One-click checkout works with EUR presentment
- Iyzico hidden/disabled when EUR active with explanation message
- Seller payout logic unchanged (always TRY)
- `tsc --noEmit` passes
  </acceptance_criteria>
