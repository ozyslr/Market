    - Add import for `getTotalStock, getDefaultWarehouse, setWarehouseStock` from `./warehouseService`.

    - **Update `decreaseProductStock`**: After reading the product doc, check if the product has warehouse stock assignments. Call `getTotalStock(productId)` — if `totalQuantity > 0`, the product has warehouse-managed stock:
      - Get the seller's default warehouse via `getDefaultWarehouse(product.sellerId)`.
      - If a default warehouse exists, call `setWarehouseStock(defaultWarehouse.id, productId, newQuantity)` where `newQuantity` is the decremented amount from the default warehouse's current stock.
      - If no default warehouse exists, fall back to product-level stock (existing behavior).
      - If `totalQuantity === 0` (no warehouse allocation), use existing product-level stock logic unchanged.
      - **CRITICAL**: The existing product-level `stock` field on the product doc should still be decremented as before. Warehouse stock is an *additional* layer — both product.stock AND warehouseStock are kept in sync. This ensures existing queries that read `product.stock` still work.
      - Specific algorithm:
        1. Read product doc and existing warehouse assignments.
        2. Get total warehouse stock via `getTotalStock(productId)`.
        3. If product has warehouse stock AND a default warehouse exists:
           - Get the specific warehouseStock doc for the default warehouse + product.
           - Decrement the default warehouse's stock by quantity.
           - Also decrement product.stock as before.
        4. If product has warehouse stock but NO default warehouse:
           - Decrement product.stock only (warehouse stock stays — partial alloc case).
        5. If product has NO warehouse stock:
           - Decrement product.stock only (existing behavior, unchanged).
      - The `recordStockChange` calls after the transaction must also pass `warehouseId` when available.

    - **Update `restoreProductStock`**: Mirror the same algorithm as decreaseProductStock but adding stock instead of subtracting:
      - Same `getTotalStock` + default warehouse check.
      - Increment the default warehouse's stock for the product when applicable.
      - Always increment `product.stock` as before (backward compatible).

    - **DO NOT** change the function signatures of `decreaseProductStock` or `restoreProductStock` — they are called from Checkout, orderService, and returnService with the existing `(items, meta?)` shape. Warehouse detection is internal.

    - **DO NOT** modify `validateCartStock` — it reads `product.stock` from the product doc, which still gets decremented. No change needed.
