# Quick Task 261102-ra8: Seller product flow + security fixes

## Problem

Approved sellers cannot add products: Firestore rules gate products on custom claims
(`token.role == 'seller'`, `token.sellerId`) but no approval path ever sets them.
Meanwhile several endpoints/rules let any signed-in user escalate.

## Root causes (from audit)

1. 5 approval paths (AdminSellers.handleReview, AdminSellers.setKyc, AdminSellerView.handleApprove,
   AdminSellerView "Mark as Verified", kyc.ts /admin/review + auto-approve) — none set claims.
   AdminUsers role change writes only the Firestore doc.
2. approve-tr/eu look up `sellerApplications/{uid}` but app ids are `app-<ts>` → 404.
3. kyc.ts: admin routes only verify token (any user can approve self / change settings); no ownership checks.
4. /api/v1/keys: any token (incl. anonymous) mints keys with arbitrary permissions → Admin-SDK product writes.
5. products rules: no sellerId binding on create, status/sellerId/rating mutable on update.
6. storage products/\*\* writable by any authenticated user.
7. users create rule lets a user create own profile with role 'admin'; commission.ts trusts users.role.
8. sellers owner can flip own kycStatus/isVerified; sellerApplications create can set status 'approved'.
9. BulkEditBar writes status 'Active'.

## Tasks

- T1 `server/lib/sellerAccess.ts` grantSellerAccess(uid): claims {role:'seller', sellerId: uid} (never downgrade admin),
  users.role='seller', sellers.kycStatus='verified'. Endpoint `POST /api/admin/seller/:uid/grant-access` (verifyAdmin).
  Harden `/api/admin/set-claims`: whitelist keys, sellerId forced = uid for sellers, sync users.role.
- T2 kyc.ts: admin routes require role=admin; submit/kvkk/contract/status require owner (or admin);
  approve + auto-approve call grantSellerAccess.
- T3 approve-tr/eu: resolve application by doc id OR userId; grant access on success.
- T4 Client: admin approval paths call grant-access; AdminSellerView uses application.id for reviewApplication;
  AdminUsers role change via set-claims; AuthContext force-refreshes token when profile role ≠ claim role.
- T5 /api/v1/keys requires seller claim + permission whitelist; API PUT content edits reset status to pending;
  commission.ts uses token role.
- T6 firestore.rules (products, users create, sellers protected fields, sellerApplications create) +
  storage.rules products/{uid}/\*\* + ProductForm upload path + BulkEditBar statuses.
- T7 `scripts/backfill-seller-claims.mjs` (dry-run default, `--apply`).
